首先是WAF的绕过：

题目非常神秘地拦截了有or的payload中有空格的写法，而且联合查询中前后的两个参数都做了引号的闭合，因此会有a' UNION SELECT '1的写法，但是这道题更难过的地方，在于注入点不同于常规的任意位置，而是限定在了password的地方。看上去以后得先好好定位再说了：

之后就到了我们熟悉的步骤：

  1. 确定order数：password位：111' UNION SELECT 1,2,3,4'，需要注意这里两个参数都需要带上引号；
  2. 表名（sqlite不能爆database()）：111' UNION SELECT name,2,3,4 FROM sqlite_master'，得到的表里有一个叫secret_flags的，大概就是它了；
  3. 列名：111' UNION SELECT sql,2,3,4 FROM sqlite_master',这里并没有用常规的' UNION SELECT name,NULL FROM pragma_table_info('users')-- -写法来查询列名，自己试了一下，pragma似乎也会被waf，这么看只有看所有的列名了。此时注意到：CREATE TABLE secret_flags(id, flag_value, note)，因此flag应该就在flag_value这个列里。
  4. flag：111' UNION SELECT flag_value,2,3,4 FROM secret_flags'即可。

总结：本题利用一个不常见的sqlite数据库，补充了笔者先前只会mysql的可怜境地。且对于这种waf的拦截，可以学习ai的“最小化探针”逐步进行测试。对于sqlmap，笔者尝试使用却一直返回假阴性，询问ai之后得知是默认测试样例的锅，随后会进行补充学习。

– 看上去对于sqlmap，第一默认的加空格的载荷会被waf拦截；第二，对于' AND '1'='1和' AND '1'='2都会返回403禁止访问，对于它的布尔判断器会失效。能看出来出题人想让大家学会sql的基本原理。

而在上面这个回答的下面，dsh提出要“寻找定时任务”，颇为不解，于是：



也就是说，对于这种情况，我们可以先通过如下命令扫用户的文件权限：

find / -xdev -writable -type f 2>/dev/null或
find / -xdev -type f -perm -o+w 2>/dev/null | wc -l

  而对于后面一种，作用只是查询当前用户的权限，但是用户www-data是在同名的用户组里的，这样查询并不妥帖，应该用前一条命令测实际的读写情况。
得到：
var/lib/teahouse/cleanup.conf可以写入，且这个会被计划任务（删除tmp目录的那个）执行。

找到计划任务后，我们直接修改它执行的外部文件cleanup.conf，给它加上一行cp /flag /var/www/html/storage/out.txt; chmod 644 /var/www/html/storage/out.txt，等待计划任务执行即可。

– 总结：

  1. 文件上传不要为单个后缀名的限制而气馁，可以尝试多个后缀名（如本题.phtml），对于黑名单模式很有用；
  2. 对于文件的“提权”，核心并不是一个死板的sudo -l，而是先找到当前文件系统最鲜明的特点（如本题的corn计划任务），以及当前用户/组可写的文件，而这个文件又能够由更高权限的用户（如root）执行。提权并非使用户chmod，而是利用root执行的最高权限夹带私货，从而绕过限制。

[!NOTE] 来自dsh老师的教诲
知识点 · 为什么本机地址黑名单必然失败
黑名单是字符串匹配，而"同一个主机"有无数种等价写法：十进制/十六进制/八进制 IP、
短写（127.1）、IPv6 映射（[::ffff:127.0.0.1]）、0.0.0.0、DNS 重绑定、@ 混淆……
更根本的是，只解析 host 也不够——还要考虑重定向、DNS 解析结果。
正确做法：白名单（只允许明确的域名/协议）+ 解析后校验目标 IP 是否落在内网段。
