3.询问llm，得知这道题属于js原型链污染的范畴：

原型链是js中的一个重要概念，大致就是对于任意对象都存在一个公用的父对象，称为原型对象Object.prototype，可以调用它里面的一些方法和属性，而proto就是指向这个原型对象的指针。

这也就解释了一点：原型被所有对象共享，污染一处，处处生效（当然本题并不需要这么多东西）

以上单独出现的proto都是指外面有下划线，长得像魔术方法的那个，md不知道怎么就渲染成加粗了

而本题考点属于 服务端原型链污染（Server-Side Prototype Pollution, SSPP） 下的一个具体分支：

通过 __proto__ / constructor.prototype 污染 Object.prototype，实现属性注入与权限绕过（Privilege Escalation）。

更直白地说：**利用不安全的递归合并（deep merge）污染全局对象原型，让后端在检查 isAdmin、canReadFlag 时从原型链上读到 true。**以下给出ds大人的总结：

  • 后端使用了不安全的递归合并/深拷贝（如 lodash.merge、自定义 deep merge 等）。
  • 合并函数没有过滤 __proto__、constructor、prototype 等键。
  • 后续权限校验读取的是 user.isAdmin、user.canReadFlag，且没有用 hasOwnProperty 检查属性是否属于对象自身。
  • 你的输入能够到达这个合并函数（比如通过更新 profile 的接口）。

这段话描述的即为http请求走私，其中“货箱长度”即为CL（Content-Length），而“分块清点”则是Transfer-Encoding，柜台和后舱就是前后端。- > 得出该部分要求以CL.TE的模式进行请求走私，于是我们在一再的试错后，在fish一串字母师傅和dsh的指点下，得出如下报文：

但是对于这段http报文，我们有如下几个注意点：

  • CL.TE模式下，由于前端只认content-length，我们需要手动数清楚后面包括0和两个CRLF之后的走私内容，将它们统计到CL里头，从而让前端把他们当作普通的body发出去；而在后端，由于只认TE的分块传输，每个块又以0和两个RLF作为默认截断，后头的请求就会被当作第二个http请求，从而实现走私。
  • 对于http发包，我们不能过于依赖浏览器默认发出来的报文，往往只需要用请求，Host，CL,TE,Connection，Cookie等自己需要的部分即可（或者改用curl，笔者决定于近期把这个学会
  • 我们在鉴权的时候并不是总用Cookie和session。比如对于JWT的校验，一般情况下就可以使用Authorization: Bearer ，这种方式常见于JWT和Oauth，我们将这个模板的解释放在下面：

“Authorization: Bearer” is an HTTP header format used to transmit access tokens, allowing clients to authenticate and access protected resources securely.
